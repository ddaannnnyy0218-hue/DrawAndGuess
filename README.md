# 画里有话 · Draw & Guess

面向朋友小群的网页绘画猜词游戏。电脑、平板、手机均通过浏览器参与。

## 第一版已实现

- 昵称与 8 个原创动物头像，无需游戏账号。
- 创建私人房间，分享邀请链接，或输入 6 位房间码。
- 2–8 人轮流绘画，三个候选词，猜词与画手双向计分。
- 日常脑洞、校园现场、英语画猜，共 150 个基础题目。
- 30 / 40 / 60 / 90 秒绘画时长，每人画 1 或 2 次。
- 12 色画笔、粗细设置、橡皮、撤销、清空、触屏操作。
- 多人共享画布、猜词消息、表情回应、每轮揭晓。
- 刷新恢复当前玩家和画布；房主离开自动转移；离线宽限 45 秒。
- 结算排行榜、本局画作回顾、PNG 保存、一键再开。
- 独立单人练习画布。

## 技术结构

React 19 + TypeScript + Vinext，Cloudflare Worker API，D1 / SQLite。

| 文件 | 用途 |
| --- | --- |
| app/page.tsx | 首页、房间、对局、结算 |
| components/drawing-board.tsx | 鼠标和触控画布、工具栏 |
| lib/game.js | 服务端规则、权限、猜词、计分、状态迁移 |
| lib/canvas.ts | 规范化笔画重放，跨屏幕保持相同比例 |
| lib/words.js | 内置词包和英文别名 |
| app/api/game/route.ts | 游戏 API |
| db/schema.ts、drizzle/ | 数据库模型和迁移 |
| tests/game.test.mjs | 真实 SQLite 上的服务端集成测试 |

这版使用 HTTP 短轮询同步：画笔约每 140 毫秒分段提交，接收端在上次请求完成后约 650 毫秒拉取增量；实际延迟取决于网络与请求时间。

服务器维护回合与截止时间。答案和候选词只发送给画手；猜词者收到脱敏状态。房间修改通过版本号进行条件写入，防止多人同时猜中时覆盖分数。笔画有独立去重键，网络重试不会重复写入。笔画查询按房间、回合、游标隔离，刷新后可重建画布。

浏览器 sessionStorage 仅保存当前房间的玩家凭证；localStorage 仅保存昵称和头像偏好。连续 24 小时未更新的房间与笔画，会在下一次创建房间时清理。

## 本地运行

需要 Node.js 22.13+ 和 pnpm。

~~~sh
pnpm install --frozen-lockfile
pnpm build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_far_loki.sql
pnpm dev
~~~

数据库迁移仅在该本地数据库首次准备时执行。以后增加表结构，应生成新的迁移并按顺序应用。

首次运行后，打开命令给出的本地地址。使用两个浏览器窗口的独立会话测试两名玩家。局域网跨设备测试时，需要正确配置服务监听地址与防火墙。

## 当前边界

- 首版只有经典画猜。接龙与假答案投票尚未实现。
- 尚无公开匹配大厅、账号系统、语音聊天、AI 识图或用户自定义词包。
- 中途加入需等待本局结束；短时掉线可用原会话恢复。
- 同步采用短轮询，适合小规模试玩；高并发运营前应进一步压测并评估 WebSocket / Durable Objects。
- 应用的私人房间和托管平台的访问权限分开管理。托管站点初始为私人预览；邀请其他人试玩前，站点访问范围也需要允许这些访客。
- 测试涵盖服务端集成和生产构建；本次环境未提供可用的浏览器测试能力，尚未完成真实浏览器视觉验收。

## 下一步验证

邀请 4–6 位同学完成一局，记录从打开页面到进入房间需要多久；是否有人卡在选词、猜词或换人；结束后是否主动再开一局。优先用这些反馈改进核心流程，再决定是否增加画图接龙。
